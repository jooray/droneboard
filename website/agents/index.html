hand it to your agent.

An AI coding agent can do two jobs for you from start to finish: make a personal dictionary out of text you have already written, and add a language Droneboard does not have yet. Each job has a Markdown guide the agent reads on its own. Everything runs on your computer.

a personal dictionary from your own text

  1. 01

    what it does

    You type words no dictionary has: family names, streets, company and project names, jargon. The agent reads text you have already written (notes, sent mail, your own chat messages), finds the words Droneboard does not know yet, cleans the list and writes a file. You import that file in the keyboard. The tool only reads and writes files on your computer.

  2. 02

    what the agent needs

    Python 3.8 or newer, the tool personal_dict.py (one file, standard library only), the Droneboard APK from the latest release and your text. The tool reads the built-in dictionaries out of the APK, so words the keyboard already knows are not added again.

  3. 03

    the guide

    personal-dictionary.md says where to look for text, how to take only your own messages from a chat export, which three commands to run, how to clean the word list, what the import file looks like and how to get it onto the phone. It is also a skill: copy it into your agent's skills folder.

  4. 04

    say this to your agent

    Read https://cypherpunk.today/droneboard/agents/personal-dictionary.md and build me a personal dictionary for the Droneboard keyboard from my own writing. My text is in <folder or file>. I type in <languages>. Keep everything on this computer and show me the list before I import it.

  5. 05

    then, on the phone

    In Droneboard 0.2.1 or newer open Settings → Text correction → Personal dictionary → Import from file. It shows how many words are new and adds them after you confirm. Words that are already there stay. The same screen imports the dictionary exported from Gboard, if you only want to move the words you added there by hand.

teach droneboard a new language

  1. 06

    what a language consists of

    A main dictionary for tap typing, a swipe word list with word-pair and word-triple statistics, an emoji dictionary, a small neural next-word model that runs on the phone, and a keyboard layout. Each part is built from open data with scripts in the repository.

  2. 07

    what the agent needs

    A checkout of the latest main, Python and disk space for the corpus. The neural model is trained with MLX, so it needs an Apple Silicon Mac. The guide says what each step downloads and how long it takes.

  3. 08

    the guide

    new-language.md covers how to check that a language is feasible, where our data came from and how to find the same for another language, the commands for dictionaries and n-grams, training, exporting and verifying the model, and every file in the app that has to change. The commits that added Hungarian serve as a worked example. It ends with how to measure the result and what to put in the pull request.

  4. 09

    say this to your agent

    Read https://cypherpunk.today/droneboard/agents/new-language.md, check out the latest https://github.com/jooray/droneboard and add <language> to Droneboard: dictionaries, swipe word list and the neural next-word model. Before you start, tell me what data you want to download and how long training will take.

  5. 10

    send it back

    A language that works for you will work for the next person too. Open a pull request at github.com/jooray/droneboard with the built files, the commands you ran and the numbers you measured.

facts an agent should know

  1. 11

    the project

    Droneboard is an open-source Android keyboard (GPL-3.0), a fork of HeliBoard. Its application id is today.cypherpunk.droneboard. It has no INTERNET permission, so everything it uses ships in the APK or is imported from a file by the user.

  2. 12

    where things are

    Source: github.com/jooray/droneboard. The APK is in GitHub releases. Dictionary tooling is in tools/dicts, neural model tooling in tools/lm, swipe replay and evaluation in tools/swipe-replay. File formats are described in native/droneswipe/FORMAT.md and docs/dictionaries.md.

  3. 13

    plain text for machines

    The two guides are Markdown files with stable addresses, listed in llms.txt. They are copies of files in the repository and are rebuilt with the website.

  4. 14

    limits

    The personal dictionary cannot be filled over adb. Android lets only the keyboard write it, so the import happens in the app. Swipe typing works on single words in the Latin alphabet. The swipe encoder weights come from FUTO under their own licence.
